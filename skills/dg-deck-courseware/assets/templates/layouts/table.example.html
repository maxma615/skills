接下来，认一认四块板的 BPU。RDK X5 的架构叫 Bayes-e，单核，10 TOPS，用 hb_mapper 转换，板端模型是 .bin。S100 是 Nash-e，单核，80 TOPS；S100P 是 Nash-m，单核，128 TOPS；S600 是 Nash-p，有四个 BPU 核，最高 560 TOPS。这三块 S 系列板，都用 hb_compile 转换，板端模型是 .hbm，而且用的是同一个工具链镜像。至于工具链的版本号，以工具链文档为准。
Toolchain

两条板卡线的工具

转换在 x86 电脑的官方 Docker 里做，不在板上做。

步骤RDK X5S 系列（S100 / S100P / S600）
导出四块板一样：PyTorch 导出 ONNX。
模型检查hb_mapper checker --march bayes-ehb_compile -m <model> --march nash-*
量化编译hb_mapper makertbin → .binhb_config_generator + hb_compile -c → .hbm
板端推理四块板统一用 Python 的 hbm_runtime，或 C/C++ 接口。
RDK 小课堂 2-01
认识 BPU · 两条工具线15 / 24
落到具体工具，分两条板卡线。导出这一步都一样，从 PyTorch 导出 ONNX。模型检查：X5 用 hb_mapper checker，S 系列用 hb_compile 加上 march 参数。量化编译：X5 用 hb_mapper makertbin 生成 .bin；S 系列先用 hb_config_generator 生成配置文件，再用 hb_compile 生成 .hbm。这些转换都在 x86 电脑上的官方 Docker 里完成，不在板子上做。到了板端推理，四块板都可以用 Python 的 hbm_runtime，本课程也统一按 hbm_runtime 来讲。
